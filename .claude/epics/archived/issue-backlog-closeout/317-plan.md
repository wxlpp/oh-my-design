# #317 实施计划：位图 1-LSB 偶发红

## 铁律

**先查机理，再改判据；不预设结论、不当噪声重跑。** issue 自己写明了顺序：
① 查 `expectBitmapsEqual` 离屏渲染在 macOS 是否本就不保证逐字节确定；
② 若是，判据形态改（容差 / 感知比较 / 换钉性质）；
③ 取样量提到可分辨量级。

## 步骤

### 1. 读装置

- 读 `expectBitmapsEqual` 实现（在 `Tests/OhMyDesignEffectsTests/` 内，名字搜索）；
  搞清渲染路径（SwiftUI `ImageRenderer`？`CGBitmapContext`？）。已知两个落点：
  `MaskRevealTests` 的「chrome 可被 SwiftUI 插值」、`TextAndDisplayTests` 的
  「端点上被盖住的那一层完全不参与合成」（行号已漂，按测试名找）。

### 2. 确定性实验（核心证据）

同一进程内重复渲染同一视图 N 次（N ≥ 50），统计：差异次数 / 差异字节数分布 /
每处是否恒 ≤ 1 LSB。再跨进程重复。产出**数据**而不是印象：
- 若 50 次零差异 → 逐字节确定性在本机成立，偶发红另有来源（继续查触发条件）；
- 若偶发 1-LSB 差 → 离屏渲染本身不确定，进入第 3 步。

### 3. 按机理选判据形态（三选一，按证据选）

- **容差**：每处差 ≤ 1 LSB 且差异字节数 ≤ 小常数。⚠️ 阈值**不得照着噪声现值定**
  （仓库记忆「下界照着坏输出定就是给 bug 发绿灯」）——先构造真实缺陷的签名再定：
  两条测试各注入一个真实逻辑错（如「隐藏层以 5% alpha 参与合成」/「插值不绑
  progress」），量真实缺陷会产生多少差异字节，阈值须远低于它。
- **感知比较**：换用感知色彩距离。
- **换钉性质**：如 alpha 直方图相等 / 均值+分布界——须能证明等价地钉住原性质
  （「完全不参与合成」与「动画中间值真的是部分揭示」）。

### 4. 变异实证（换族）

- 判据改造后注入真实逻辑错 ⇒ 必须红（这是「容差化」最常见的病：连真错也放过去）。
- 构造 1-LSB 级噪声注入 ⇒ 必须绿（新判据对旧噪声免疫）。

### 5. 取样收敛证明

- 修复后连跑两条涉及 suite 的目标测试 ≥ 10 遍（或按统计口径跑够），记红率。
- 全量 `swift test` 一遍留证。

## 验收

- 一份确定性实验数据（N 次渲染差异分布）决定机理结论。
- 判据形态有真实缺陷签名作阈值依据；变异实证双向（真错红 / 噪声绿）。
- 取样记录 + 全量绿，关闭评论附数据。
