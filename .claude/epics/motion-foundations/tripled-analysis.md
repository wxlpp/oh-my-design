## 1. 结论摘要

工作量 S ≈ 半天内、M ≈ 1–3 天、L ≈ 一周级。TripleD 是「复制粘贴 + Framer Motion」的 Web 动效库，绝大多数条目是营销区块、玻璃卡片和 hover 驱动交互；**真正值得拿的是十来个「原子交互」，而且其中一半在 SwiftUI 上有原生 API，本仓只是一处都没接**。所以 P1 不是新组件，是把 iOS 17/18 原生动效 API 接进现有小件，加一层动效 token / Reduce Motion 纪律。

### P1

1. **把 `symbolEffect` / `contentTransition` 接进现有小件**——`anchoredBadge` 的计数用 `.contentTransition(.numericText(countsDown:))` + 出现/消失 `.transition(.scale.combined(with: .opacity))`；`CheckBoxToggleStyle` / `RadioGroup` 的 `if/else` 双 `Image` 淡变改成同一个 `Image` + `.contentTransition(.symbolEffect(.replace))` + `.symbolEffect(.bounce, value:)`；`StateLabel.inProgress` 可选 `.symbolEffect(.rotate)`。对应 TripleD `native-likes-counter`（计数按方向上下滚）、`native-notification-bell`（铃铛 wiggle + 徽标 scale 0→1）、`animated-checkbox` / `animated-radio`（spring 500/30 缩放勾选）、`heart-favorite`。全是原生 API，零新类型。**OhMyDesign，S**
2. **`CoreMotion` 动效 token + 核心库 Reduce Motion 纪律**——12 处时长字面量收成 3–4 档（`press 0.16 snappy` / `select 0.2 snappy` / `reveal 0.25 easeOut` / `dismiss 0.25 easeInOut`），并给 Toast 滑入、TopBarIndicator、Segmented / TabBar thumb、`ButtonBackgroundModifier` 补 Reduce Motion 分支（缩放 → 透明度、位移 → 淡入淡出，与 `PressableCardButtonStyle:65-67` 已有做法同形），再加一条与 Effects `MicroInteractionReduceMotionGuard` 同族的核心库判据。TripleD 的 `MotionConfig reducedMotion="user"` 是这件事的 Web 版；本仓 Effects 已有更好的机制，只是核心库没铺。**OhMyDesign，M**
3. **TagGroup / TagInput 的增删与选中动画**——两者今天零 `withAnimation`（`TagGroup.swift:106` 直接赋值、`TagInput.swift:40,88` 直接改数组），而且 `TagInput.swift:38` 用 `id: \.offset` 让 identity 动画根本做不了。对应 TripleD `detail-task-card`（assignee chip 退场 `{opacity 0, scale 0.9, y -8}` 0.2 s + `popLayout`）。改 `id` 为内容、加 `.transition(.scale(0.9).combined(with: .opacity))` + `withAnimation(.snappy)`；`FlowLayout` 是 `Layout`，位置补间免费。**OhMyDesign，S**

### P2

4. **`CountUpText`（数字滚入）**——TripleD `native-counter-up` / `stats-counter-block`：`animate(0, value, { duration 2, ease expo-out })`，reduce motion 直接跳终值，`aria-live="polite"` 只读终值。SwiftUI 无「从 0 滚到 N」的原生封装（`numericText` 只做位数翻滚，不驱动中间值），用 `Animatable` modifier 驱动 `Text(value, format:)` + `.monospacedDigit()`，RM → 直接终值，`accessibilityValue` 只报终值。**OhMyDesignEffects（文本与展示组），S/M**
5. **`TypingIndicator`（三点呼吸 = "正在输入 / 思考中"）**——TripleD `ai-response-typing`（三点 scale 1→1.2→1 / opacity 0.5→1，1 s，错开 0.2 s）。Messages 的原生成例，本仓「处理中」组只有扫光三件套，没有行内小件。`phaseAnimator` 三相即可；RM → 三点静止；走 `EnergyState.presentation` 统一门。**OhMyDesignEffects，S**
6. **`TypewriterText` 三处补强**——① 标点后加长停顿（`ai-response-typing-shadcnui.tsx:36-52`：`. , ! ? \n` 后 `speed × 3`），打出来的节奏立刻「像人」；② 可选光标（`native-typewriter` 的 `cursor` 0.5 s reverse 闪烁）；③ `startDelay`。本仓 `TypewriterText.swift:129-135` 是等间隔 `Task.sleep` 单向递增，`prefix(of:count:)`（L42-45）没有光标，文档已把「光标闪烁」登记为同槽装饰候选（`typewriter-text.md`「登记」节）⇒ 加参数不触发扩展点重判。多词循环 + 回删（`native-typewriter` 的 `loop` / 2 s 停留 / 半速回删）降到 P3——那是 hero 文案的玩法。**OhMyDesignEffects，S**
7. **`FloatButton` 展开成动作组（Liquid Glass 形变）**——TripleD `native-morphing-button`（FAB 56×56 圆 ↔ 280 宽圆角卡，spring 300/30，动作项错开 0.05 s 滑入，Esc 关闭、焦点回 FAB）。本仓 `FloatButton` 没有展开形态（`float-button.md` 与源码搜 `menu|expand` 零命中），而 **iOS 26 的 `GlassEffectContainer` + `glassEffectID(_:in:)` 正是 Apple 自己给「一个玻璃按钮展开成一组玻璃按钮」定的形变通路**——这是本仓「玻璃只用于浮层」定案下唯一合法、且目前零使用的形变 API。零成本替代是 `Menu` + `.buttonStyle(.glass)`，先在文档写清两者取舍再决定做不做。**OhMyDesign，M**
8. **`SlideToConfirm`（滑到底才触发）**——TripleD `drag-to-confirm-slider`（`drag="x"` 0→200、≥180 判成功、否则弹回；进度驱动标签淡出、把手加宽 48→248）。Apple 自家「滑动来关机 / SOS」是同一形态，HIG 允许用于高代价动作；SwiftUI 无原生。`DragGesture` + `sensoryFeedback(.success)`；VoiceOver 必须给 `accessibilityAction` 直接确认（拖不动）；RM 不影响（手势驱动，与 `BeforeAfterSlider` 的判定同理，`before-after-slider.md:243-257`）。只在有真实消费方（支付 / 删除账户）时做。**OhMyDesign，M**
9. **Steps / Timeline 连线的推进动画**——TripleD `wizard-form-shadcnui.tsx:80-82`（连线 `height 0%→100%` 0.4 s 随完成态）、`timeline-block-shadcnui.tsx:79-80` / `interactive-timeline`（`scaleY 0→1` 0.8 s、节点 `scale 0→1` 错开 0.2 s、进入视口才播）。本仓两者的连线**现状不同**（原写「两者都是按状态二选一填色的静态 `Rectangle`」，对 Timeline 为假）：`Steps.swift` 确实按状态二选一填色（`if self.progress(for: index) == .done` 分支填 `.tint` / `Color.dividerDefault`）；`Timeline.swift` 的 `TimelineConnector` 是**无条件** `.fill(Color.dividerDefault)`，连状态都不读。把连线改成 `trim` / `scaleEffect(y:, anchor: .top)` 随 `current` 补间（S）；「进入视口才播」用原生 `.scrollTransition`（不要 IntersectionObserver 那套）。**OhMyDesign，S/M**
10. **Segmented / TabBar 的 thumb 改 spring + TabBar 补选择触感**——TripleD `animated-tabs` / `native-tabs` / `animated-navbar` 一律 `layoutId` + `spring(stiffness 300–380, damping 30)`（`native-tabs` 是 `spring(duration 0.45, bounce 0.15)`）。本仓 SwiftUI 回退路径是 `.easeInOut(duration: 0.18)`（`SegmentedControl.swift:100`）、TabBar 是 `.snappy(duration: 0.22)`（`UnderlinedTabBar.swift:37`）；后者已是 spring 族，前者换成 `.snappy` 即与 iOS 26 原生 `UISegmentedControl` 的手感更近（原生分支是 UIKit 自带的动画，`SegmentedControl.swift:316-370`，不动）。`UnderlinedTabBar` 没有 `sensoryFeedback`，与 SegmentedControl 不一致。**OhMyDesign，S**

### P3

11. `RotatingText(words:period:)`（`native-flip-text`：`rotateX -90→0→90` + blur 6 + `AnimatePresence mode="wait"`）——本仓 `.transition(.flip)` 与 `.transition(.blur)` 都已在 Effects，只差一个按周期换 `id` 的小容器；hero 副标题用途，RM → 直接淡变。**Effects，S**
12. `staggered(index:)` 入场 modifier（`animated-list`：`staggerChildren 0.12`、item `x -20→0` 0.4 s；`staggered-dropdown` 0.05 s 步长）——SwiftUI 无 stagger 原语，`.transition(.offset+opacity)` + `.animation(.delay(Double(index) * step))` 一行封装；HIG 里错落出现只用于一次性揭示（Wallet 卡片），不进列表滚动。**Effects，S**
13. 「进入视口才播」与「阅读进度条」都只写**文档 recipe**——`scroll-reveal` 用 `useInView(once, margin -15%)`，SwiftUI 原生 `.scrollTransition(.animated(.snappy)) { content, phase in content.opacity(phase.isIdentity ? 1 : 0).offset(y: phase.value * 20) }`；`scroll-progress-tracker` 用 `useScroll` + `useSpring`，原生 `onScrollGeometryChange` → `ProgressView(value:).progressViewStyle(.core)`。两个 API 本仓零使用，不值得做类型。**docs，S**
14. `Marquee`（`native-marquee`：双副本 `x: 0%→-100%` 线性无限循环、`pauseOnHover/Touch`、竖向）——`docs/contract-defects.md` D-299-2 已裁定 marquee 是 `OrbitingLogos` 之外的「另一个组件」而非其变体，故这里是新增而非扩展；Music 的歌名滚动是 Apple 成例，但本仓消费方多半是 logo 墙（营销）。常驻渲染必须接 `EnergyState`（`.paused` 时不建 `TimelineView`）、RM → 静态截断。**Effects，M，观望**
15. `ConfirmableDestructiveButton`（`native-delete`：Delete → 展开 Confirm + X，spring bounce 0 / 0.35 s，图标与文案 `mode="wait"` 交叉淡变）——UIKit 表格编辑态「减号 → Delete 滑出」是同形态；HIG 高代价动作仍优先 `confirmationDialog`，低代价（撤销一条评论）才适合行内确认；需自动回退计时 + VoiceOver 公告。**OhMyDesign，S/M，观望**
16. `SelectionCheckOverlay`（`native-image-checkbox`：未选灰度 + 选中角标勾 `scale 0→1`）——Photos 多选的角标勾是 Apple 成例，灰度不采；与 `anchoredBadge` 同属「贴角 overlay」，可复用其 placement 枚举。**OhMyDesign，S，观望**
17. `AsyncButton` 的**瞬时成功态**（`native-start-now`：loading → success label blur-swap 0.2 s；`native-liquid-button` 的 `success` / `error` 布尔）——本仓 `AsyncButton` 只有 loading（label 隐藏 + spinner）；「✓ 已复制」这类 1 s 成功态是 Apple 常见形态，用 `.contentTransition(.symbolEffect(.replace))`。**OhMyDesign，S**
18. `Skeleton` / `TopBarIndicator` 接 `EnergyState`（`.paused` 时不建 `TimelineView`）+ 扫光加 ease-in-out——`ai-loading-skeleton` 的扫光 1.5 s linear 与本仓 1.4 s linear 一样，没有可借之处；但本仓两处常驻 30 fps `TimelineView` 不接能耗闸是 Effects 与核心库之间的口径差。**OhMyDesign，S**
19. `Rating` 步进触感（`sensoryFeedback(.selection, trigger: value)`）；`Carousel` 触摸期间暂停自动播放（`native-marquee` 的 `pauseOnTouch`；`carousel.md` 已登记「拖拽中定时推进不会跳过」）。**OhMyDesign，S**
20. `PinCode` 校验失败 → `.shake`：核心库不能依赖 Effects，只能在 `pin-code.md` 写 recipe（`.shake(trigger: validation)`）。**docs，S**

## 5. 横切观察

### 5.1 「原生 API 零使用」是最大的一笔可得收益
上面 P1-1 与 B 表前三行的共同点：TripleD 用几十行 Framer 代码做的事，SwiftUI 在 iOS 17/18 已经是一行 modifier（`numericText` / `symbolEffect` / `scrollTransition` / `onScrollGeometryChange`），而本仓三个 target **一处都没接**。这比新增任何组件都便宜，且不增加 public API 表面。

### 5.2 动效 token 与 Reduce Motion 纪律：Effects 有、核心库没有
Effects target 有统一门（`EnergyState.presentation(reduceMotion:)`）、有台账判据（`MicroInteractionReduceMotionGuard` / `ReduceMotionGuard`）、有 3 档 `RenderPolicy`；核心库只有 3 个组件读 RM、两处常驻 `TimelineView` 不接能耗、12 处时长字面量。TripleD 虽无 token，但「每个含位移的组件都读 `useReducedMotion`」这条纪律它做到了 90%+（本轮 digest 里 50+ 文件命中）。建议把 Effects 的机制往下铺到核心库（P1-2），而不是反过来学 TripleD 逐文件手写。

⚠️ 写判据时注意 `component-contract.md:710`「把 Bool 换成两 case enum 不是替代路径」——「动效开 / 关」不要做成 `MotionSetting { on, off }`；RM 走系统环境值（§3.4「优先复用系统环境值」），能耗走已有的 `EnergyState`。

### 5.3 Liquid Glass 形变是本仓玻璃定案下唯一还没用上的 iOS 26 能力
`glassEffectID` / `GlassEffectContainer` / `glassEffectUnion` 全仓 0 处。TripleD 的 Morphing Button / Notch / Expanding Search 那一族「一个圆 ↔ 一张卡」形变，在 Apple 平台上恰好只在浮层合法，而本仓浮层组件（FloatButton / Toast）都在。P2-7 是唯一一个建议用它的点；其余形变需求（搜索、Dynamic Island）都由系统承担。

### 5.4 触感是 TripleD 给不了、本仓也没铺开的一层
Web 无触感，TripleD 零 `vibrate`。本仓只有 SegmentedControl 一处 `.sensoryFeedback(.selection)`；`UnderlinedTabBar` / `Rating` / `TagGroup` / `SlideToConfirm`（若做）都是选择型交互，HIG 建议配 `.selection`。这是本仓相对 Web 库的**顺手超集**，成本一行。

### 5.5 计数口径
TripleD 去重后 180 条：A 表建议新增 / 轻封装 **9**（CountUpText、TypingIndicator、FloatButton 展开、SlideToConfirm、RotatingText、staggered、Marquee、ConfirmableDestructive、SelectionCheck；后 3 条为观望）、写 recipe 不做类型 **5**、B 表现有组件优化 **16 行**、C 清单覆盖其余 **~150** 条（含全部 Blocks / Pages）。
