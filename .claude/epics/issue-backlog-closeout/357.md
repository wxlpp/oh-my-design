# 任务：#357 coreAccent 饱和色深色反色

规格见 issue 正文（`#356` 终审 I-2 / spec R-5 承接）。**API 已裁决（2026-09-14，用户）：
派生缺省 + `on` 参数可覆盖**。

## 范围

- `View.coreAccent(_:on:)`：新增可选 `on` 参数；缺省按 accent 亮度自动选黑 / 白
  （墨色 accent 行为与现状逐字节一致：亮度派生在 light/dark 下恰好复现 `systemBackground`）；
  显式 `on` 覆盖自动选择。
- 消费点改为读环境解析后的 on-accent：`ButtonRoleStyleRole.onColor`（五 role）、
  `InkSegmentedControlStyle` 选中段文字。
- 静态 token `contentOnAccent` 保留（分层前提不破），作为回退值。
- 三处已登记文档同步：`CoreAccentEnvironment.swift` 文档注释、`docs/DESIGN-FOUNDATION.md`
  accent 衍生族一节、`docs/BREAKING-CHANGES.md` 未发布章节。
- 验收判据：`.coreAccent(<饱和色>)` 下 `solid(.primary)` 按钮前景 / 背景在明暗两档
  对比度足够（口径参考 `#356` 的 `ButtonRoleStyleRole.onColor` 文档注释里的对比度表，
  注意那条表在 iOS 腿实测、资源色不进 macOS 腿 `resolve(in:)` 断言的仓库约束）。

## 已知坑

- 亮度派生需在**当前外观**下取值（`Color` 解析受 colorScheme 影响）；判据别在
  macOS native 腿解析 asset catalog 色（见 CLAUDE.md《验证边界》）。
- MainActor 棘轮：新增公开 `static` 成员检查 `scripts/mainactor-static-ratchet.sh`。
- `downstream-probe` 同步（`View.coreAccent` 签名变化是 source-compatible，probe 加新调用点即可）。
