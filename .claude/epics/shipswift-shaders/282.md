草案说「B-2（17 个）注定要按纯噪声 / 多 pass / 需 SDF 再拆」。剩 **8 个**、
边际成本 **1–1.5 小时/个**（#248 实测）⇒ 合计 8–12 小时，与 `shipswift-effects`
#250（8 个 modifier，单 task，L / 12–18h）同量级。**再拆是为了凑数，不做。**

## 成本口径已反转

#249 第 1 版说「多数走 clean-room，比移植贵」。**本版相反**：8 个里 7 个是
**带署名的移植**（paper，Apache-2.0），移植**比** clean-room 便宜，但多了
**Apache-2.0 的署名义务**：转载 LICENSE 全文 + 转载 `NOTICE`
（`Powered by Paper Shaders: https://shaders.paper.design`）+ **标注修改**（§4(b)）
+ 逐 shader 的 `.metal` 文件头注明 paper 的对应 `.ts` 路径。

## Acceptance Criteria

- [ ] 8 个各有 `public struct … : View`，可 `.background { }`
- [ ] **`.metal` 侧零硬编码色**（FR-8）；调色板全部走参数
      ⚠️ #261 已实证：**shader 读不到 `.tint`**——`TintShapeStyle` 是 `ShapeStyle`，
      SwiftUI 不提供把它解析成 `Color` 的途径，而 Metal 需要分量 ⇒ tint 以**参数**形式
      传入、默认值取第 3 层语义 token。沿用 #261 的形态，不要另发明一套
- [ ] **Reduce Motion**：冻结在某一帧（保留视觉、去掉运动），不是停止渲染
- [ ] **NFR-7 后台 / 低电量**：经**注入伪值测试**可证。
      ⚠️ 两个可注入键（`lowPowerModeOverride` / `scenePhaseOverride`）已由
      `shipswift-effects` #252 落在 **`Sources/CoreDesign/Environment/EnergySignalEnvironment.swift`**
      （**不是** `CoreDesignEffects`）⇒ 本 target 已依赖 `CoreDesign`，**`import CoreDesign` 即可**，
      不需要 `import CoreDesignEffects`
- [ ] ⚠️ **#271 必须先裁决**：通用能耗策略表（`drawsAnything` / `minimumInterval` 与
      「`scenePhase != .active ⇒ 停摆`、`lowPower ⇒ 降帧`」这条映射）**仍在
      `CoreDesignEffects`**。本 task 只有两条路：(a) `import CoreDesignEffects`
      ⇒ **推翻下沉的全部理由**；(b) 从两个键自行再写一遍同一条映射 ⇒ 必漂。
      **#271 自己写着「B-2 开工前裁决最便宜，一旦 B-2 落件并 `import`，搬动就是破坏性变更」**
- [ ] **像素采样的 render proof**（沿用 #261 的 `RenderProofTests` 形态）
      ——⚠️ #261 的教训：metallib 加载通过 + 函数解析通过，**画出来的每个像素仍可能一模一样**
      （`Float` 精度：`timeIntervalSinceReferenceDate` ≈ 8.1e8 在 `Float` 下只剩约 16 个单位
      精度，把 0…11 的空间项整个吞掉）。失败形态是「效果看起来是静态的」，四条腿全绿
- [ ] `ACKNOWLEDGEMENTS.md` 的 **Apache-2.0 + NOTICE 段**已就位（骨架由 #249 建）
- [ ] 各有 `#Preview`；`EffectsColorLiteralGuard` 对本批零违规
- [ ] **Bool 纪律**（AD-H）：本 epic 的 Bool 豁免预算 **≤ 1 条**（全局 3 = Effects 2 + Shaders 1），
      每条有书面理由并按棘轮脚本抬基线
