# Task: 已落地 8 件的 provenance 清偿（4 个 `TBD` 承接编号 + 强指纹 + 漏分档）

## 背景：#261 落的 8 个，**没有一个在可落地 11 里**

`docs/shader-provenance.md`《统一裁定表》里，PR #261 落地的 8 个 shader
（`Plasma` / `Starfield` / `Dots`(`DotGrid`) / `FractalClouds` / `InkSmoke` /
`LiquidChrome` / `Glass`(`RefractiveGlass`) / `GlassLogo`(`GlassSymbol`)）
**全部裁定为 `待追溯`**，而该裁定的定义是「**不得据现状落地**」。

《清偿条款》正是为这个矛盾写的：

> 本表如果原样合入，会把 #261 从"未裁定"变成"已裁定为不得落地"——比合入前更糟。
> 「一条被它唯一的消费者在第一天就违反的规则，不是规则。」

⇒ 裁定：`待追溯` 按指纹强度分两档，**只有强档阻断落地**；低档不阻断，
条件是 **ⓐ 不作任何原创声称、ⓑ 有具名承接 issue（合入 `main` 前编号必须填实）、
ⓒ 下一次该文件被实质修改时必须追完**。

**本 task 就是那个「具名承接 issue」。**

## ① 填实 4 个 `TBD`（ⓑ）

《清偿条款》的分档表里，四行低指纹项的「承接 issue」列现为 `TBD`，
而文档规定「`TBD` 一律视为**未清偿**，`epic → main` 的 PR 评审须逐行核对已换成真实编号」。

- [ ] `ramp3` —— 承接编号填 **#281**
- [ ] `edgeWidth` —— 同上
- [ ] `wangHash` —— 同上
- [ ] Teschner 素数三元组 —— 同上

⚠️ **不是只填编号就算清偿**。分档表自己写着 `ramp3` 那一行的分档理由**未引判据原文**、
`edgeWidth` 的 ①② 两条判据**系本表认定而非引自他处**，两处都指名「须在承接 issue 里复核」：

- [ ] `ramp3`：补齐 ①（复制量小）②（常数/结构是功能性的）③（来源为无许可的公开发表）
      三条判据评估。⚠️ 补齐前该行分档按「**有争议一律按强档处理**」随时可被翻成强档
- [ ] `edgeWidth`：复核本表自行认定的 ①②
- [ ] `wangHash`：记住「**逐字符一致**」这个事实——它不改变分档，改变的是
      **不得作任何原创声称**这条的严格程度
- [ ] Teschner：⚠️ **两表打架**——《共享原语的逐项出处》判它「论文里的常数 ⇒ **事实性算法，
      可落地**」，而《清偿条款》分档表把它列为**待追溯（低指纹）**。二者必须收敛为一个结论
