# Task: 扫描根收口 —— `CoreDesignShaders` 进 `GuardScanRoots` + 10 个 public 类型登记

## 问题：整合时会当场红，而现在两条分支各自都绿

`#246` 交付的 `Tests/CoreDesignTests/GuardScanRoots.swift` 逐字写着：

> `Sources/CoreDesignShaders/` 今天**不存在**，故**不进**本表：对它做扫描/grep 无命中即绿，
> 正是要防的 fail-open。**该根由 `shipswift-shaders` 的 B-1 在 target 真的落地时加入。**

`targetNames` 现为 `["CoreDesign", "CoreDesignEffects", "CoreDesignCharts"]`，
而 `libraryTargetsAreCoveredByScanRoots` **直接解析 `Package.swift` 里声明的 library target，
与本表做双向差集**。

- `epic/shipswift-shaders` 上：`Package.swift` **已有** `CoreDesignShaders` library（PR #261），
  但该分支**还没有 `#246`**（其提交里没有 `#265`）⇒ 守卫不存在 ⇒ 绿。
- `epic/shipswift-effects` 上：守卫在，但 `Package.swift` 没有 Shaders ⇒ 差集为空 ⇒ 绿。
- **两条分支一整合，该判据当场红。**

⚠️ 这正是 `#246` 自己写下的「新 target 静默逃出全部守卫」通路被机器堵死的效果——
判据按设计工作了，但**没人接**这笔账。

## 第二笔账：8 个 shader 类型对组件登记表结构上不可见

`ComponentRegistryGuard.coreDesignSources` 是单根 `Sources/CoreDesign`
（`#270` 正在为 Effects / Charts 的 8 个类型收口这件事）。
`CoreDesignShaders` 有同样一批未登记的 public 类型：

`DotGrid` / `FractalClouds` / `GlassSymbol` / `InkSmoke` / `LiquidChrome` / `Plasma` /
`RefractiveGlass` / `Starfield`（8 个 View）+ `CoreDesignShaders`（命名空间 enum）
+ `ShaderSupport.swift` 里的公开面。

⚠️ **`#270` 的射程不含它们**——那个 issue 逐条点名的是 `Shine` + 四个图表 + 三个 Effects 件。
本 task 是 Shaders 侧的同款收口。
